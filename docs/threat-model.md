# Threat model

Unofficial DagzTagz project. Not an xAI, SpaceXAI, or Grok product. This runtime does not call the Grok API. The full list of roles it does not fill is in [getting-started.md](../getting-started.md#what-this-tool-is-not).

The program is written for four neighbors of the folder:

- Another account on the same virtual machine, who can write wherever the directory mode allows.
- A bad `git add`, including a force-add, that would publish the private key or the notes.
- A forged snapshot, a file that looks signed and was edited after the stamp.
- An agent that claims the task is done when the forged fixture was never rejected, the decay clock never moved, or the key mode was never checked.

It is not written as a defense against the root account, a stolen unlocked session, or a disk image taken while the key file is open. Modes `0700` and `0600` are the sharing rules. The same table is in [SECURITY.md](../SECURITY.md), with the reporting steps.

| Id | Failure | What the code does | What a person would see |
|----|---------|--------------------|-------------------------|
| T1 | A private key lands in git, a log, `evidence.md`, or a world-readable file | Key bytes stay in `crypto.py`. Export does not copy `identity/`. If a verified fork contains PEM-shaped text, `fork_verified.json` is replaced with JSON `null`, the scan line does not repeat the marker, and `pass` stays false. | `REJECT`, then `vesper: audit checks failed`, exit 2. `fork_verified.json` is `null` and a newline. `find` for `edcsa-p256.priv`, `hmac.key`, and `identity` prints nothing. The evidence scan line says the fork copy was withheld. |
| T2 | Schema drift: missing fields, wrong types, unknown properties | `schema check` reports problems. `schema heal` fills documented structural defaults. It rejects a missing character id, universe id, schema version, or forks list. Unknown properties are kept. Reserved names `__proto__`, `constructor`, and `prototype` are rejected. | `schema check` on the drifted fixture prints `schema invalid` and exits 2, and the fixture is unchanged. Heal of a file with no character id exits 2 and does not replace the file. A healed copy still shows the same `character.id`. |
| T3 | Fork forgery: wrong key, mutated body, detached signature | `verify` rebuilds the canonical body, checks the key id, and checks the signature. A kid that does not match the public point is reason `kid` before `bad_signature`. | `vesper verify fixtures/forged-fork.json` prints `vesper: bad_signature` and exits 2. Exit 2 is the expected result for that file. Exit 0 would mean a bad stamp was accepted. |
| T4 | A parent link breaks, or an old snapshot is replayed as the new head | `parent_hash` must match the parent file. The filename stem must match `name`. `created_unix` must not go backwards. An identical `state_hash` to the parent is a replay. `verify --head` ignores a sibling that does not verify. A sibling that verifies with a larger `created_unix` is a replay. JSON `true` is not a timestamp. | Stderr is `vesper:` plus `parent_missing`, `parent_hash`, `replay`, `name`, or `cycle`, and the exit code is 2. A junk sibling does not by itself fail the head. A newer signed sibling does. A crash that saved the new file and not `state.json` still looks like `replay`. |
| T5 | Memory poisoning: unbounded STM, NaN weights, path characters in ids | STM cap is 100. Non-finite weights are rejected. Ids are a single safe segment: `[A-Za-z0-9._-]`, length 1..128, no `..`. | A note past the cap still exits 0, and the oldest `(ts, id)` is gone from `state.json`. A non-finite weight or a bad id prints `vesper:` and exits 2. Text outside 1..4096 characters exits 2. |
| T6 | Paths escape the workspace | The workspace root is explicit. `..`, absolute paths, and symlinks that leave the root are rejected. A symlinked workspace root is refused. | A name containing `..` exits 2. A workspace path containing `..` exits 2. A missing workspace prints `workspace does not exist` and exits 3. A symlink used as the workspace root exits 3. |
| T7 | A process uses a mode `0644` private key, or a workspace directory other accounts can replace | The key is opened with `O_NOFOLLOW`. Mode is `fstat` on that descriptor. Anything other than `0600` is refused and is not chmod'd into shape. The identity directory must be `0700`. Init sets the workspace directory you named to `0700` and does not chmod its parents. `schema heal --write` keeps an existing mode that is a non-zero subset of `0644`. | A `0644` key stays `0644`. The next use prints `vesper: refusing key that is not mode 0600` and exits 3. A wrong directory mode prints `vesper: identity is mode 0644; directory must be 0700` (the actual mode and the filename are filled in) and exits 3. After init, `stat` shows the workspace directory as `700`. |
| T8 | Tests are green while forged-signature or decay cases never ran | `vesper export` runs those checks and writes the commands into `evidence.md`. A suite that skipped them does not get `"pass": true`. | A skipped check prints `REJECT` and exit 2. `score.json` has `"pass": false`. `evidence.md` shows `python -m pytest -q` and `vesper verify fixtures/forged-fork.json; echo EXIT:$?`. The forged line's stdout contains `EXIT:2` when that check passed. Hand-editing `score.json` is not what export writes. |

`verify` never promotes a matching stamp into a legal identity. It tells you the file still matches the key material the file itself names (ECDSA) or the workspace HMAC key (HMAC).
