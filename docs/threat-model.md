# Threat model

Unofficial DagzTagz project. Not an xAI, SpaceXAI, or Grok product. This runtime does not call the Grok API. The roles this tool does not fill are in [getting-started.md](../getting-started.md#what-this-tool-is-not).

These eight rows are the failures this version is written to catch. The same rows are in [SECURITY.md](../SECURITY.md), next to the reporting steps. A finding that is not one of these rows is recorded in [disclosurebulletins.md](../disclosurebulletins.md). The `python-ecdsa` timing leak, DB-001, is one of those findings. It is not fixed by T1 through T8.

The program is written against four neighbors of the folder.

- Another account on the same machine, who can write wherever the directory mode allows.
- A `git add`, including a force-add, that would publish the private key or the notes.
- A snapshot that looks signed and was edited after the stamp, or an older snapshot offered as the newer one.
- An agent that claims the task is done when the forged sample was never rejected, the decay clock never moved, or the key mode was never checked.

It is not a defense against the root account, a stolen unlocked session, or a disk image taken while the key file is open. Mode `0700` and mode `0600` are the sharing rules. The program does not listen on the network, so these rows do not describe a remote attacker.

`verify` does not turn a matching stamp into a legal identity. It tells you the file still matches the public point stored in that file, for ECDSA, or the workspace HMAC key, for HMAC.

## T1 through T8

| Id | Failure | What the code does | What you see |
|----|---------|--------------------|--------------|
| T1 | The private key is copied into git, a log, `evidence.md`, or a file other accounts can read. | Key bytes are handled in `src/vesper/crypto.py`. The identity object's text form does not include them. Export does not copy `identity/`. After the audit folder is written, every file in it is scanned. A hit is a symlink, a file named `edcsa-p256.priv` or `hmac.key`, or bytes that contain the private-key markers. On a hit, `fork_verified.json` is replaced with the four characters `null` and a newline, `no_secrets_in_export` stays false, and `pass` stays false. The scan line does not repeat the marker. `public.json` is refused if it contains that same marker text. Git itself is not intercepted. `.gitignore` lists `workspace/`, `*.priv`, and `hmac.key`, and a force-add can still publish a listed file. | `REJECT`, then `vesper: audit checks failed`, exit `2`. `fork_verified.json` is `null` and a newline. `find` for `edcsa-p256.priv`, `hmac.key`, and a directory named `identity` prints nothing. `evidence.md` says the fork copy was withheld. |
| T2 | The notes file has drifted: a required field is missing, a type is wrong, or a reserved name appears. | `schema check` compares the file with `fixtures/dagztagz-uni-schema-v2.json` and does not change it. Unknown fields are kept. `__proto__`, `constructor`, and `prototype` are rejected. `schema heal` adds only the documented holes: missing memory lists, a missing `pinned`, a missing note `tier`, a missing `user_weight`, a missing `seed`, and a clamp of a finite weight into `0` through `1`. It does not invent `universe_id`, `schema_version`, `character.id`, `character.callsign`, `character.straussian_level`, `memory`, `forks`, note text, or an edge's `id`, `src`, `dst`, or `rel`. A `tier` that disagrees with its list is rejected by heal. `schema check` does not make that list comparison. The field rules are in [schema.md](schema.md). | `vesper schema check fixtures/drifted-state.json` prints `schema invalid` and exits `2`. The fixture is unchanged. It fails because `semantic`, `graph`, `ltm`, and the note's `tier` are missing. `pinned` is optional, so it is not the reason. Heal of a file with no character id exits `2` and does not replace the file. A healed copy of the drifted fixture still has `character.id` `char-drift`. |
| T3 | A snapshot was signed by the wrong key, edited after the stamp, or given a signature that does not belong to the body. | `verify` rebuilds the canonical body, which is every field except `signature`. It checks `kid` against the public point, then checks the stamp. A kid that does not match is reason `kid`, and that result is returned before `bad_signature`. ECDSA verify uses `public_key_hex` inside the file and does not open the workspace. HMAC verify loads `identity/hmac.key` only after `algo` is `hmac-sha256`. The check order is in [forks.md](forks.md). | `vesper verify fixtures/forged-fork.json` prints `vesper: bad_signature` and exits `2`. That file's name and key id match. The stamp does not. Exit `2` is the expected result. Exit `0` would mean a bad stamp was accepted. |
| T4 | The parent link is broken, the filename does not match the signed name, or an older snapshot is presented as the current head. | Both `parent_id` and `parent_hash` are JSON `null` on the first snapshot. If one is a string and the other is not, the reason is `parent_hash`. If both are strings, the sibling `<parent_id>.json` must exist and its content fingerprint must equal `parent_hash`. A missing parent file is `parent_missing`. A parent path that is a shortcut is `parent_hash`. `created_unix` earlier than the parent is `replay`. An equal time is allowed. An identical `state_hash` is `replay` even when the clock moved. A repeated parent name is `cycle`. The filename stem must equal `name`, or the reason is `name`. `verify --head` also requires `fork_index` to match the head file, or the reason is `replay`. A neighboring `.json` file with an illegal stem fails the head with `name`. A neighboring file that does not verify is ignored, including broken JSON. A neighboring file that verifies with a larger integer `created_unix` is `replay`. JSON `true` is not a timestamp. If opening a neighbor raises `ValidationError`, `CryptoError`, `IOPermissionError`, or `OSError`, the head check returns `canonical`. | The error stream is `vesper:` plus `parent_missing`, `parent_hash`, `replay`, `name`, `cycle`, or `canonical`, and the exit code is `2`. A junk neighbor with a legal filename does not by itself fail the head. A newer signed neighbor does. A crash that writes the new snapshot and does not update `state.json` still returns `replay`. This version does not repair that window. `--allow-orphan` records waiver id `orphan-parent` only when the parent file is absent. It does not skip a parent that exists. |
| T5 | Notes are poisoned: the short-term list grows without a cap, a weight is not a real number, or an id contains a path. | `remember` caps `stm` at 100. The drop is the smallest `(ts, id)`, and it happens on append, not during `sleep`. A non-finite weight or valence is rejected. Valence must already be inside `0` through `1` and is not clamped. A finite weight is clamped into `0` through `1` and rounded to 10 decimal places. Text must be 1 to 4096 characters. An id is one segment of `[A-Za-z0-9._-]`, length 1 to 128, with no `..`. `NaN` and `Infinity` are rejected when JSON is parsed, before a note is stored. The sleep numbers are in [memory.md](memory.md). | Adding the 101st short-term note still exits `0`, and the oldest `(ts, id)` is gone from `state.json`. A non-finite weight, a valence outside `0` through `1`, a bad id, or text outside 1 to 4096 characters prints `vesper:` and exits `2`. |
| T6 | A name or a shortcut points outside the workspace. | The workspace root is the directory you pass. A root path whose parts include `..` is rejected before the path is resolved. A symlinked workspace root is refused. A joined name must pass `validate_name`: it rejects `..` anywhere in the string, including `a..b`, an absolute path, a slash or backslash, and a null byte. An existing shortcut is resolved. If that target is outside the workspace root, the join is rejected and nothing is written through it. A shortcut whose target stays inside the root is not rejected by that test. Writes use `O_NOFOLLOW` and refuse to follow a shortcut. | A bad name exits `2`. The message says the name rejects `..`, an absolute path, or a path separator. `vesper fork --name ../alpha` exits `2`, and a `forks` shortcut that points outside the workspace does not receive the new file. A workspace path containing `..` exits `2` with `workspace path rejects '..'`. A missing workspace prints `vesper: workspace does not exist:` and the path, and exits `3`. A symlink used as the workspace root exits `3` with `workspace root is a symlink`. |
| T7 | A private key is mode `0644` or any mode other than `0600`, or the workspace directory is one that another account can replace. | The key is opened with `O_RDONLY` and `O_NOFOLLOW`. The mode is `fstat` on that same descriptor. Anything other than exactly `0600` is refused, including `0640` and `0644`, and the file is not changed. The identity directory must be exactly `0700`. Extra bits such as setgid fail that check. The directory is not repaired. `init` sets the workspace directory you named to `0700` after `mkdir`, including when the process umask is `0`, and it does not change parent directories. `schema heal --write` is a different write. It keeps an existing regular-file mode that is a non-zero subset of `0644`, so a `0600` notes file stays `0600`. It does not carry the private key, and it does not repair a weak key. | A `0644` key stays `0644`. The next read prints `vesper: refusing key that is not mode 0600` and exits `3`. A directory that is not `0700` stays at that mode and prints `vesper: identity is mode 0755; directory must be 0700`, with the real mode and the directory name filled in, and exits `3`. After `init`, `stat` shows the workspace directory as `700`, `identity` as `700`, and `edcsa-p256.priv` as `600`. |
| T8 | The test suite is green while the forged-signature check, the decay clock, or the key-mode check never ran. | `vesper export` runs seven checks and writes each command into `evidence.md`. Those checks are `schema_heal_or_reject`, `forged_signature_rejected`, `parent_chain_ok`, `key_mode_enforced`, `memory_decay_ran`, `path_traversal_rejected`, and `no_secrets_in_export`. `pass` is true only when every one of them is true and, when you run export from the terminal, `python -m pytest -q` exits `0`. If export is already running inside pytest, a second pytest is not started. The seven checks still have to pass. A green pytest run does not fill `score.json` by itself. The decay check requires a semantic weight of `1.0` to stay `1.0` when `now` equals the note's `ts`, and to become smaller when `now` is ten hours later. The names and verdicts are in [audit-export.md](audit-export.md). | A failed check prints `REJECT` and exits `2`. `score.json` has `"pass": false`. `evidence.md` shows `python -m pytest -q` and exactly `vesper verify fixtures/forged-fork.json; echo EXIT:$?`. When the forged check passed, that command's output contains `EXIT:2`. Editing `score.json` by hand is not what export writes. |

## What this table does not claim

A matching `verify` does not prove who you are in law, and it does not prove the note is true. Mode `0600` does not hide a file from root. `shred -u -n 1` overwrites the named file once and unlinks it. On an SSD, a copy-on-write disk, or some VM disks, that overwrite may not reach the old blocks. This program does not wipe free space. DB-001 remains an accepted timing limitation of `python-ecdsa` until `crypto.py` uses a different P-256 implementation.
